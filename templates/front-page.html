06 · Methodology and System Discipline

How I approach engineering

Five stages, run in order and repeated whenever the requirement changes underneath the work.

  • Understand. What the system actually has to do, what it must never do, and where the real constraint sits.
  • Design. Component boundaries, data flow and the failure cases, decided before any code is written.
  • Build. Small changes, each one reviewable on its own.
  • Verify. Test the failure path, not only the happy one. An unprivileged user should not be able to bypass the interface and call an endpoint directly.
  • Improve. Simplify what the work made harder than it needed to be.
